01概览与页面地图

面向家庭成员（父母维护，祖辈观看）。全站不含预约、价格、套餐、摄影师与任何表单。核心原则：照片挂在故事下面，年龄只做筛选。

图片

首屏 contain 不裁切，最大宽 76vw、最大高 72vh；列表卡 cover 3:2 / 3:4；统一滤镜 sepia(.1) saturate(.94) 用于拉齐不同来源的色温；加载失败显示浅色占位块，不出现破图。

动效

区块入场：上移 24px + 淡入 700ms，只播一次；图片 hover 仅 1.02 缩放；翻页 280ms 交叉淡入；禁自动轮播、禁视差；prefers-reduced-motion 全部关闭。

03数据模型

五张表。人工必填仅三项：孩子生日、六位家人的关系与参考照、时区。其余由流水线生成。

表字段
peopleid · relation(enum) · name · ref_photos[] · appear_count
mediaid · file · type(photo|video) · taken_at · duration · time_source(exif|file|manual) · quality_score · scene_tags[]
facesmedia_id · person_id · bbox · confidence
storiesid · title · title_candidates[3] · period_start · period_end · type(event|series) · age_range · cover_media_id · status(draft|published)
story_mediastory_id · media_id · order_no · role(cover|lead|inline|archive)

一条故事的返回结构

  "title": "走路这件事",
  "period": { "start": "2021-03-14", "end": "2021-11-02" },
  "type": "series",
  "age": { "from_month": 11, "to_month": 19 },
  "counts": { "photos": 23, "videos": 1 },
  "people": ["妈妈", "外婆"],
  "scenes": ["家里", "小区"],
  "cover": "md_0182",
  "video": { "media_id": "md_0347", "duration": 42, "position": 0.65 },
  "text": {
    "deck": "他第一次松开手，是三月的一个下午。",
    "body": ["三月的那个下午……", "从那天到他自己走出家门……", "现在回头看……"],
    "pull": "他走得很慢，我们跟得更慢。",
    "source": "generated+human_note"
  },
  "status": "published"
}

文案生成依赖三段输入：事实层（时间、人数、张数、月龄）、推断层（动作、场景、表情）、留白层（家人补的一句）。缺第三层时只写事实，不编造心理与对话。

套壳工程里的落地

五张表在 Android 端落成四张：people · media · stories · story_media。人脸框不持久化，聚类结果只用来累计 people.appear_count；需要回溯时可再加一张 faces 表。

方法路径作用
GET/api/bootstrap摘要数字 + 人物列表，上传确认页顶部四项
GET/api/drafts本次批次的全部故事，含已确认的，前端据 status 渲染完成态
POST/api/drafts/{id}/accept接受一条草稿 → published
POST/api/drafts/accept-all接受本批次全部高置信度，返回影响行数
POST/api/drafts/{id}/rename?title=改名
GET/api/stories · /api/stories/{id}已发布列表 / 单条故事（带 media，按 order_no 排好）
GET/api/today「N 年前的今天」，取覆盖今天的故事

故事表比上面多两个字段：batch——标出「属于本次上传批次」，已确认的也要能回到列表，否则页头写的「全部 18 / 待确认 15 / 已确认 3」对不上；ai_note——AI 给自己这一行写的说明，直接显示在标题上方，比前端按置信度套模板更准。
