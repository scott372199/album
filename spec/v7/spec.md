## 0. 一句话

V7 把产品从「**按年份归档的个人相册**」收敛为「**按年龄讲故事的成长影像册**」：结构锚点从「年 → 月」换成「**他几岁 → 故事集 → 一个故事 → 一张照片**」；用户不再分类、不再建相册、不再写字，只做两件事——**接受或改一个标题**；交付形态是**一份 HTML 双端可跑**（浏览器静态页 + Android 套壳）。页面公开可浏览，**写入（上传/接受/改名）必须经验证**。

*V7 re-anchors the product from an album archived by year to one that narrates growth by age. Pages are publicly readable; every write path is authenticated. The user stops classifying: AI drafts stories, the family only accepts or renames.*

## 1. 目标与成功标准 / Goals and Success Criteria

### 1.1 目标 / Goals

1. **结构换锚**：访问者打开册子，第一眼看到的是**一张照片和它属于哪一年**，一屏之内能点到「他几岁」；不再有「相册」这个需要先理解的概念。
   *The first screen is a photograph and the year it belongs to; the age shelf is one screen away. There is no "album" concept to decode first.*
2. **分类归零**：从导入到成册，用户**不被要求做任何分类决策**——不选相册、不填标签、不写标题。
   *Zero classification decisions between import and publish: no album picker, no tags, no writing.*
3. **文案看孩子**：每句话的主语是孩子或他身上的东西，不出现拍摄者，不解释数据；AI 只出候选，最后一句留给人。
   *Every line is about the child, never about the person holding the camera, never about the data.*
4. **两端同源**：一份 HTML 同时跑在浏览器和 Android 壳里；差别只在数据来源（静态 / Room），不在页面与交互。
   *One HTML codebase, two hosts; only the data source differs.*
5. **守住写入口**：页面公开只读；任何写入（上传/接受/改名/发布）都必须经验证，凭据不进页面；浏览时零外部生成请求，不新增常驻资源与月成本。
   *Read is public, every write is authenticated, and no credential ever ships inside a page — with zero runtime generation and no new always-on infrastructure.*

### 1.2 成功标准 / Success criteria

| # | 指标 | 现状（V6 生产 / 本版设计稿） | V7 目标 |
| --- | --- | --- | --- |
| S-1 | 用户完成一次导入要做的分类决策 | 1 次（上传必填「放进哪个相册」，默认当年） | **0 次** |
| S-2 | 文案主语是「记录者」的比例 | 9/9（「第一次注意到…」「拍得最多…」） | **0/9**，且由 FR-05 五条判据自检 |
| S-3 | 从首页到一个具体故事的点击数 | 3 层（时间轴 → 年月 → 灯箱） | **≤2 层**（年龄 → 故事集 → 故事内页） |
| S-4 | 一个故事能被独立阅读的比例 | 0（只有照片流，没有「一件事」） | **≥1/3 的草稿**有正文或旁白，其余保留「只有人名与地点」的诚实状态 |
| S-5 | 顶栏可点动作数 | 6 项（时间轴/相册/故事/照片墙/上传/搜索） | **≤3 项**（品牌 / 字 / 返回） |
| S-6 | 浏览时外部生成请求 | 0 | **仍为 0** |
| S-7 | 单页体积 / 六个产品页合计（不含图片与字体） | 最大 27.7KB / 96.0KB | 单页 **≤40KB** / 合计 **≤120KB** |
| S-8 | 双端一致 | 无 Android 交付 | 同一 HTML 在浏览器与 App 内均可打开；App 内「上传确认页」读写本地库成功 |
| S-9 | 未验证写入的成功率 | 无写入通道（V6 无上传） | **0%**（拒绝而非静默忽略）；页面内凭据数 **0** |

## 2. 范围 / Scope

EARS 记法：**当**（事件）/ **在 … 时**（状态）/ **若**（异常）/ **必须**（shall）。
*EARS notation: WHEN (event) / WHILE (state) / IF (unwanted condition) / SHALL.*

### 2.1 结构：他几岁 → 故事集 → 故事 → 单张

#### FR-01 首页

**当**家人打开册子时，系统**必须**先给一张照片，再给出口。

- 首屏为单张（`object-fit: contain`，**不裁切**，桌面 76vw × 72vh），叠一行「01 / 08」计数与一句图注；← → / 点两侧 / 左右滑翻页，**280ms 交叉淡入**，一次只换一张。
- 首次进入 0.7s 后浮出「← → 翻页 · 点击图片看大图」，3.5s 淡出；**同一会话只出现一次**，且 `prefers-reduced-motion: reduce` 时不浮出。
- 首屏之下依次为：一句主张 →「八年前的今天」→ **他几岁**（4 栏年龄入口）→「这一年」（3 行错位 12% / 6%）→「同一个窗口」（时间轴）→「谁在身边」（6 位家人 + 出镜次数）→ 外婆留言 → 留给家里。
- 「他几岁」的四栏**必须**是链接，分别进入对应年龄的故事集；hover 时露出「全部 N 个故事 →」。
- 顶栏可点动作**不得**超过 3 项：品牌 / 字（长辈模式）/ 返回相册。
- 点击照片进灯箱；**若**图片加载失败，**必须**显示浅色占位块（内联 SVG data URI），不得出现破图图标。

**验收**
- 1440×900 与 390×844：未滚动状态首屏**必须**是一张完整照片，且能看到「01 / 08」；不出现半张照片、不出现横向滚动条。
- 点「他几岁」任一栏 → 落到对应年龄的故事集页，且筛选状态为空（全部故事）。
- 翻到第 8 张再按 → 回到第 1 张，计数同步；快速连按 5 次不出现空白帧。
- 顶栏可点项 ≤3。

#### FR-02 四层结构

**当**用户从任一入口进入时，系统**必须**落在四层中的某一层，且每一层都能原路返回上一层。

- 四层：**年龄货架（他几岁）→ 故事集列表 → 故事内页 → 单张（灯箱）**；时间轴「同一个窗口」是并行的二级入口，不进主链。
- 年龄货架以**月龄区间**命名（「1–3 岁」），不以「2021 年」命名；年份只在故事卡上作为副信息出现。
- 故事卡**必须**带三样信息：标题、时间区间、张数（含视频时加「· N 段视频」）；跨年重复出现的标 `系列`。
- **若**某个年龄下没有故事，**不得**渲染空货架卡，宁可不显示该栏。

**验收**
- 首页 → 他几岁 → 1–3 岁 → 走路这件事 → 大图 → 浏览器返回四次回到首页，每次落在原滚动位置（误差 ≤40px）。
- 四层任一层刷新后仍停在该层（浏览器端用文件名，App 端用同一份 HTML）。

### 2.2 故事集与故事内页

#### FR-03 故事集列表

**当**用户进入某个年龄时，系统**必须**给出一列**故事**，而不是一列照片。

- 每张卡：封面（3:4 裁切）、标题、时间区间、张数；`系列` 用左上角小角标。
- 吸顶筛选条：**6 位家人** + **5 类场景**（家里 / 小区 / 公园 / 旅行 / 节日）chip；可按「时间 / 张数」排序；纯前端过滤，**无刷新、无网络请求**。
- 筛选条**不得**出现「相册」这一维——V7 已取消该概念（B-05）。
- 命中为空时给一句人话（「这个筛选下没有故事，换成外婆试试」）+ 清除入口。
- 卡片的点击目标是**整张卡**，不是标题；键盘 `Tab` 可达，`Enter` 进入。

**验收**
- 选「外婆」+「公园」后卡片数 = 数据里同时命中的故事数；点「清除」回到全量。
- 筛选与排序组合后刷新，状态不丢（浏览器端写进 `location.hash`）。
- 卡片总数与年龄货架上标的「N 个故事」一致。

#### FR-04 故事内页

**当**用户点开一个故事时，系统**必须**按「照片 — 文字 — 照片」的呼吸节奏排，不得排成图片墙。

- 段落顺序固定：大图（lead）→ 双图并排 → 正文 → 旁白（pull）→ 竖图 → **视频（约 65% 处）** → 错位双图 → 正文 → 21:9 收尾 → 归档区（折叠）→ 上/下篇导航。
- 故事正文：宋体 17px / 行高 2.15 / 栏宽 **620px**；旁白居中同栏宽；普通正文 17px / 1.85。
- 顶部 **2px 阅读进度条**，随滚动推进，到底消失。
- 视频**必须**点击才播（`autoplay` 禁止）；未播放时显示静帧 + 9s 进度条 + 左上「演示」标记（本版视频为占位交互）。
- 归档区默认折叠，显示「另有 15 张」，展开后为 4 列缩略网格，点任一张进灯箱。
- **若**故事还没有正文（AI 只识别出人名与地点，如「2021 年 7 月照片」），页面**必须**显式说明这一点，不得用模板句填满。

**验收**
- 1440×900 下正文段落行宽在 600–640px 之间；单行字数 38–44。
- 视频位置在整页 60%–70% 之间（用滚动高度比测）。
- 折叠区展开后图片数 = 卡片上「N 张」减去正文已用张数。
- 低置信度故事页面上能找到「AI 说不出这是什么事」一类明示文案。

### 2.3 文案与自动归档

#### FR-05 文案

**当**系统为一个新聚出的故事起草文案时，**必须**分三层写，缺层就诚实留空。

- **事实层**（可推导）：时间区间、人数、张数、月龄（生日 + EXIF 相减，**不用人脸估龄**）。
- **推断层**（可观察）：动作、场景、表情；只写照片里能看见的，不写心理活动。
- **留白层**（必须由人填）：家人补的一句，AI **不得**代写；没有就空着，页面留白。
- 每条草稿给 **3 个候选标题** + 一行 `aiNote`（AI 对自己这条的判断，如「检测到跨年重复场景，建议设为系列」）；默认选中第一个。
- 语感**必须**过五条判据（B-06 定稿版）：
  1. 主语优先是孩子，其次是他身上的东西；**不出现拍摄者**（我 / 拍到 / 注意到 / 记录）。
  2. 不解释数据（张数多少、为什么只有一张）。
  3. 一句话只放一个具体动作或一个具体物件，不堆形容词。
  4. 长度 10–26 字。
  5. 允许留白与平淡：「这个月没拍什么」比抒情可信。
- 生成**不得**在浏览时发生：文案在导入/构建期落库，页面只读。

**验收**
- 从库里抽 10 条文案，逐条对照五条判据，**0 条**出现「我 / 拍到 / 注意到 / 记录」。
- 每条文案 10–26 字（按 `String.length` 计，标点计入）。
- 断网状态下故事内页文案仍完整显示；Network 面板无生成类请求。
- 只有事实层的故事，页面上不出现「温馨句」占位。

#### FR-06 自动归档

**当**一次导入完成时，系统**必须**自动产出**草稿**，人等在那里只做取舍。

- 时间：读 EXIF `DateTimeOriginal`；缺失则用文件时间兜底并把 `timeSource` 记成 `file`（可被数出来，见「时间存疑」）。
- 月龄：生日固定存一处，`月龄 = 拍摄时间 − 生日`，精确到月，不做估算。
- 人物：人脸聚类只回答「这张里有谁」，**不建人物档案、不命名、不合并**（B-01 约束）。
- 场景：按场景标签归类（家里 / 小区 / 公园 / 餐厅 / 路上 / 幼儿园 / 医院 / 旅行 / 节日）。
- 事件：**同天 + 同地点 + 同人**的照片聚成候选事件，再与已有故事比对，重复的标「可能重复」。
- 置信度三分：`high`（人 + 场景 + 时间都对上）/ `mid`（有标题但候选都不满意）/ `low`（只能给时间地点）。`low` **必须**在页面上明示「AI 说不准」，不得硬编一个「2024 年家庭照片」。
- 草稿状态默认 `draft`，**没有自动发布**。

**验收**
- 一次 286 张 + 8 段视频的导入，产出 18 个草稿（其中 3 个此前已接受）；页头写的「286 张 / 8 段 / 6 位家人 / 18 个故事集」与库内计数逐项相等。
- 每一张 `timeSource != 'exif'` 的媒体都能被单独数出来（本版样例：15 张）。
- 没有任何一条草稿的标题由「年 + 月 + 照片」模板硬拼而来；`low` 的标题允许是人话占位（「未命名合集」）但页面必须给出说明。

#### FR-07 上传与确认

**当**归档跑完时，系统**必须**把草稿交给一个**只问一次**的页面。

- 三段 stepper：上传 → 自动识别 → 确认草稿；顶部四项摘要（照片 / 视频 / 已认出的人 / 生成草稿）**必须**来自真实计数，不得写死。
- 每个草稿一行：封面 + 张数角标 + 3 个候选标题 chip（第一个默认选中）+ 人物/场景 pill + 时间区间 + 置信度圆点。
- 四个动作：**接受**（`draft → published`）、**改名**（写回标题）、**合并**（并入另一条已有故事，见 A-3）、**一键接受高置信度**（批量，按钮上显示剩余数量）。
- 合并只在 `aiNote` 明确提示「可能重复」时出现；合并后源行**必须**从列表消失（或标「已并入 ——」），目标张数**必须**相应增加，不得两边都留着。
- 排序/分段：全部 / 待确认 / 已确认，三段计数随操作实时更新。
- 「已确认」的行**必须**仍留在列表里（灰显 + 「已确认」角标），这样「全部 18 / 待确认 15 / 已确认 3」才对得上。
- 底部固定条：`已确认 X / Y` + 「完成并发布到相册」。

**验收**
- 点「一键接受」后：待确认计数 = 接受前 − 高置信度数；按钮变为「已接受 N 个高置信度」并禁用。
- 点「改名」→ 输入新标题 → 该行首个 chip 变成新标题，刷新后仍是新标题（App 内落库，浏览器内不回退）。
- 点「合并」→ 选目标故事 → 源行消失、目标张数 +N；重复点同一源不重复累加。（**V7.3 前此条不适用**：页面还没有合并按钮，A-3 已定补，见 §11.2）
- 摘要四项与库内计数相等（App 内）；浏览器内打开时显式标注「演示数据」。

### 2.4 检索与回顾

#### FR-08 搜索

**当**用户想找某张照片时，系统**必须**允许他用「人 + 地点 + 事」说话。

- 输入框为宋体 32px、仅下划线、无边框；占位文案「外婆抱他的照片」；下方一行提示「用人 + 地点 + 事来说，比打字准」。
- 结果分三组：**故事集 / 照片 / 视频**；输入即过滤（本版为前端匹配），命中词 `<mark>` 高亮。
- 空结果**必须**给替代说法 chip（「外婆」「公园」「生日」），不得只显示「无结果」。
- 搜索**不得**引入「标签」概念：不显示 tag 云、不要求用户先建标签。

**验收**
- 输入「外婆抱他」能命中含「外婆」的故事集与照片，且高亮落在「外婆」上。
- 输入「显示器」（V6 的假阳性案例）时**必须**显示空态，不回退全量。
- 三条 chip 点任一能把查询替换掉并出结果。

#### FR-09 今日回顾

**当**今天是某个故事发生的同一天时，首页**必须**出现「N 年前的今天」。

- 取覆盖今天的故事（任意年份）；没有则取最近一条；都没有则整块不渲染。
- 展示为一条横带：一张图 + 一句 + 「去看看 →」；**不推送、不加红点**。

**验收**
- 用今天日期造一条测试故事，首页出现该横带，点击进对应故事内页。
- 删掉所有覆盖今天的故事后，横带消失且不留空白间距。

### 2.5 出口：导出

#### FR-10 故事卡片与年度册

**当**家人想把一个故事发给别人时，系统**必须**给**图片**，不给链接。

- 卡片尺寸 1080 × 1440（3:4），内容四行以内：标题 + 一句旁白 + 年份区间 + 张数。
- **禁止**：网址、二维码、「长按识别」、任何可反查入口的信息。
- 同时提供「一版九张」导出预览（3×3），供群发。
- 年度册（B-02 后半）：按年把「时间轴 + 每月一句 + 里程碑」排成可打印版式；**必须离线生成**，不依赖云端渲染。

**验收**
- 导出的图片按 1080×1440 输出，文字不溢出、不被裁切。
- 图片内不存在 URL、二维码图案。
- 断网状态下可生成并保存。

### 2.6 端形态与数据层

#### FR-11 浏览器端与 Android 端

**当**同一份 HTML 被放进不同宿主时，**必须**表现一致，差别只在数据来源。

- 浏览器端：单文件 HTML，直接双击可开；无框架、无构建、无外部 JS/CSS 依赖（图片与系统字体除外）。
- Android 端：单 `Activity` + `WebView`；`WebViewAssetLoader` 把 `assets/www` 映射到 `https://appassets.androidplatform.net/assets/`（等同 https 源，避开 `file://` 限制）。
- 数据：`shouldInterceptRequest` 把同域名下 `/api/*` 交给本地接口，读 Room；页面用 `fetch`，**不引入 JS Bridge**。
- 壳层行为：状态栏让位（`WindowInsets` padding）、返回键 `goBack`、长按图片存相册、视频点击才播、站外链接交系统浏览器、旋转不重载。
- **若** `/api/*` 不可用（浏览器直接打开），页面**必须**退回内嵌样例数据并显式标注「演示数据」，不得白屏。

**验收**
- 浏览器双击打开 6 个页面均无白屏、无控制台报错（除占位图网络失败）。
- App 内「上传确认页」读到 18 条草稿；接受一条后杀进程重开，该条仍是已确认状态。
- 同一页面在两端的 DOM 结构一致（除数据条目数不同）。

#### FR-12 长辈模式

**当**用户点顶栏「字」时，全站字号**必须**等比放大一级，且不破坏版式。

- 根字号 16 → 18，所有尺寸用 `rem`；行高与栏宽随之等比，不出现溢出或截断。
- 状态**不得**自动开启，只手动触发；同会话内保持。

**验收**
- 开启后故事正文由 17px 变为 ≈19px，行宽仍 ≤640px，无横向滚动。
- 开关两次后回到初始视觉（像素级一致）。

### 2.7 边界与预算

#### FR-13 读公开、写受控

**当**册子被托管时，系统**必须**把「读」和「写」分成两条路：读不需要身份，写一律要验证。

- **读**：页面与图片**公开可访问**，无需登录，允许被搜索引擎索引（不做主动 SEO，但不阻止自然收录）。这与 V6 的公开托管一致。
- **写**：上传、接受草稿、改名、发布——四类写入**必须**先行验证；未验证的写请求**必须**被拒（不接受「前端隐藏按钮」当作验证）。
- 验证的最小形态（不引账号体系）：**一次性口令绑设备**——家人在 App 内输入一次口令，设备拿到一枚短期凭据，此后 App 内的写操作直接带凭据；口令可随时作废重发。
- **页面本身不得内置任何写凭据**：静态 HTML 里不出现 token / 密钥 / 预签名 URL。写入只发生在 App 端（本地库 → 带凭据发布），页面永远是只读的。
- 公开内容的硬化：只发布**重新编码后的展示尺寸**（剥 EXIF 与 GPS），不上传原图、不出原始文件名、不出本地绝对路径。
- 元数据只存**功能性**字段：关系（爸爸/妈妈/爷爷/奶奶/外公/外婆）、生日、参考照；**不**存身份证、住址、学校、班级等识别性信息。
- 分享出去的是**图片**（FR-10），不是页面地址——公开不等于主动推广。

**验收**
- 未带凭据直接 `POST` 上传/接受/改名：**100% 被拒**（不是 200 + 静默忽略）。
- 静态产物全文检索 `token` / `secret` / `X-Amz-Signature`：0 命中。
- 任取 3 张线上图片：无 GPS、无机身序列号、无原始文件名（沿用 V6 的脱敏校验）。
- 断网状态下打开已缓存页面仍可浏览（读路径不依赖凭据）。
- 数据表里不存在「身份证 / 学校 / 住址」类字段。

> 公开与否**不影响** §2.1–§2.6 的任何产品特性：四层结构、故事集、文案、导出都与「谁能看」解耦。这条是为了防止以后再拿「要公开/不公开」当理由改产品设计。

#### FR-14 预算与门禁

**当**任一页面被改动时，体积与自包含性**必须**可被一条命令核验。

- 单页 ≤ 40KB、六个产品页合计 ≤ 120KB（不含图片、字体、文档页）。
- 每页**必须**自包含：内联 `<style>` / `<script>`，无 `import`、无 CDN、无构建产物引用。
- 门禁四条，缺一不可：① HTML 标签闭合校验；② 内联 JS `node --check`；③ 体积阈值；④ **可公开检查**——产物里不得出现凭据、预签名 URL、本机绝对路径（FR-13）。
- **若**超限或命中禁词，**必须**失败并指出是哪一页、哪一行、超出多少。

**验收**
- 人为把某页塞到 45KB，门禁失败并指名该页。
- 六个产品页当前实测：最大 27.7KB，合计 96.0KB（2026-11-16）。

## 3. 非目标 / Non-goals

以下条目**明确不做**，不因「顺手」夹带进 V7 任一阶段：

| 条目 | 不做的理由 |
| --- | --- |
| 摄影师署名 / 预约 / 价格 / 套餐 / 成片承诺 | D-01：读者只有家人，出现商业角色就变回影楼落地页 |
| 账号体系、注册登录、多租户、成员权限分级 | FR-13 只要「一枚设备凭据」这一道门，不要用户系统；有账号就有找回、改密、注销一整套成本 |
| 人脸建档、人物命名、人物合并、按人估龄 | B-01 约束；生物特征 + 有状态，需独立隐私评审 |
| 「相册」概念的任何形式回归（含手动分组） | B-05 结论：它是年份的副本，只增加决策成本 |
| 可点标签体系 / 标签云 / 标签纠正 | B-03：标签层已被故事集取代，不再维护第二套词表 |
| 评论、点赞、收藏、社交互动 | 家庭内部不需要，且引入用户态 |
| 地图视图、轨迹、地理位置展示 | 隐私红线（FR-13） |
| EXIF 参数面板、原图直出下载 | 无需求；原图会带 GPS 与设备信息 |
| 云端渲染导出（PDF/图片）、服务端 API、数据库服务 | 坚持静态与本地；导出必须离线可成 |
| 暗色模式、国际化、主动 SEO（站点地图 / 关键词 / 结构化数据） | 页面会公开可索引，但不做推广；温和的白与主动营销是两件事 |
| 视频转码服务、在线播放流 | 本版视频为占位交互，真转码列 V8 |
| 「相册预览」以外的营销页（关于我们、联系、案例） | 商业角色已排除 |

**延后但不否决 / Deferred, not rejected**

- **年度册 PDF**（FR-10 后半）：版式与分页规则待定，V7.2 先出「一版九张」与单张卡片；PDF 需要确认是用浏览器打印还是自绘分页。
- **自动切「系列」**：跨年同场景自动合并成系列（如「楼下的广场」），本版只标角标，不自动合并。
- **多主角**：现阶段只做「我们的孩子」一人；二胎/多娃留到有真实需求时。

## 4. 硬性不变量 / Hard invariants

1. **不出现商业角色**：无摄影师、无预约、无价格、无套餐、无成片承诺。
   *No commerce anywhere: no photographer credit, no booking, no price, no package.*
2. **不发明事实**：只写可推导的事实与可观察的动作；心理与对话留给家人填。
   *No invented inner life: only derivable facts and observable actions.*
3. **不给人物建档**：识别结果只用于「谁出镜」，不做命名、合并与年龄推断。
   *Recognition answers "who is in frame" only — no profiles, no naming, no age inference.*
4. **读公开、写受控**：页面可公开访问；一切写入必须验证；凭据不得出现在静态页面里；分享出去的是图片，不是入口。
   *Reading is public, writing requires a credential that never ships inside a page; what leaves the house is an image, not a way in.*
5. **零运行时生成**：文案与聚类都在导入期完成，浏览时零外部生成请求。
   *No runtime generation: everything is drafted at import time.*
6. **视觉不加装饰**：圆角 0、投影 0、全站统一滤镜 `sepia(.1) saturate(.94)`；暖赭 `#B4795A` 每页 ≤5 处。
   *No radii, no shadows, one shared filter; the accent colour is rationed.*
7. **单页自包含**：一页一文件，内联样式与脚本，无框架、无构建、无外部依赖（图片与字体除外）。
   *Every page is one self-contained file.*
8. **端能力对等**：App 专有数据只经 `/api/*`，**不得**写进 HTML；同一页面两端 DOM 一致。
   *App-only data flows through /api only; never baked into HTML.*
9. **发布是显式动作**：草稿默认可删可改，没有任何自动发布路径。
   *Publishing is always an explicit act.*
10. **预算约束真实字节**：阈值卡的是发给家人的字节数，文档页不计入（B-04 的口径修正）。
    *Budgets constrain what family members download, not what lives in the repo.*

## 5. 契约与写路径影响 / Contract and write-path impact

**关键判断：V7 仍不加服务端数据库、不加常驻计算。** 站点沿用 V6 的 S3 桶与 website 端点，只多一个只读前缀；唯一的写路径是**本地 Room 库**（App 内）与**带凭据的发布**（App → 站点）。

| 产物 / 变更 | 用途 | 归属 | 性质 | 失败落点 |
| --- | --- | --- | --- | --- |
| `children-growth/*.html`（6 产品页 + 3 文档页） | 浏览器端交付 | 独立目录 | **新增**，与 V6 现有产物无交集 | 单页打不开即回退到上一版文件 |
| `android/`（单 Activity + assets/www + Room） | App 端交付 | 独立工程 | **新增** | 编译失败不影响浏览器端交付 |
| `stories` 表 `batch` / `aiNote` | 批次归属、AI 自述 | 本地库 | 新增字段（schema v1，直接重建） | 缺字段时前端模板兜底 |
| `/api/*` 9 条路由 | 页面读写本地库 | 壳内 | 新增只读 + 3 条写（accept / rename / merge，后者 V7.3） | 接口 404 → 页面退回演示数据（FR-11） |
| `kids/` 只读前缀（沿用 `chenyouyi` 桶与 website 端点） | 公开浏览（FR-13 的「读」） | 站点静态资源 | **新增前缀**，只读 | 上传失败时旧版本继续可用（固定名 + 内容哈希双重命名） |
| 展示尺寸图（剥 EXIF） | 公开图片 | 同上 | 新增，由导入流水线产出 | 缺失时该故事降级为纯文字 |
| 设备凭据（一次性口令换取） | 验证写请求（FR-13 的「写」） | 不入库、不进页面，只在 App 私有存储 | **新增**，可作废 | 凭据失效 → App 提示重新输入口令，页面不受影响 |

**明确不新增**：服务端数据库、常驻计算、云端渲染、用户账号体系、支付、任何 `https://` 运行时外部依赖（占位图除外，且列在已知限制里）。

**公开与产品特性的解耦**：`kids/` 前缀是否对外、是否被索引，**只影响分发**，不影响 §2 的任何一条 FR。改托管方式不需要重开 spec；改四层结构、文案规则、导出形态才需要。

**浏览器端契约**：页面之间靠**文件名**跳转（交付版为中文名，App 内为 ASCII 名并由构建替换），无 hash 路由契约；V7 不引入路由库。

**双份文件的同步规则**：`children-growth/上传确认页.html` 与 `android/.../www/upload.html` 是**同一份页面**，只允许一处差异——文件名链接（中文名 ↔ ASCII 名）。同步由 `scripts/sync-assets.py` 单向派生（交付版是源），`--check` 按字节比对并进闸（见 plan §9）。

## 8. 验收草案 / Draft acceptance criteria

- **结构**：首页 → 他几岁 → 故事集 → 故事内页，四层可达且可原路返回；顶栏可点 ≤3 项。
  *Four levels reachable and reversible; ≤3 tappable items in the header.*
- **分类归零**：从导入到成册，界面不出现任何要求用户选择/填写分类的控件；只有「接受 / 改名」两个决策（S-1）。
  *No classification control exists between import and publish; only accept and rename.*
- **文案**：抽 10 条过五条判据，0 条出现拍摄者主语；长度 10–26 字；只有事实层的故事不带抒情句。
  *Ten sampled lines pass all five voice checks.*
- **自动归档**：一次导入产出草稿数、已确认数、高置信度数三个数字，与页头摘要逐项相等。
  *Draft counts on the page equal the database counts, item by item.*
- **确认页读写**：接受、批量接受、改名三种操作在 App 内落库并在重开后保持；浏览器内退回演示数据且有标注。
  *All three writes persist; the browser falls back with an explicit label.*
- **双端一致**：6 个页面在浏览器与 App 内 DOM 结构一致、无控制台报错、无白屏。
  *Six pages, identical DOM across hosts, no console errors.*
- **边界**：读公开可访问；未带凭据的写请求 100% 被拒；静态产物里 `token`/`secret`/`X-Amz-Signature` 0 命中；`/api/*` 无白名单外字段；表里无识别性字段。
  *Reading is open; every unauthenticated write is rejected; no credential strings in shipped pages; no out-of-whitelist or identifying fields.*
- **预算与可公开**：单页 ≤40KB、六页合计 ≤120KB；四条规定门禁（闭合 / 语法 / 体积 / 可公开）全部通过；人为塞一个 `Bearer` token 时门禁失败并指到行。
  *Per-page and total budgets hold; three gates pass.*
- **长辈模式**：字号放大一级后版式不破，开关两次回到像素级一致。
  *One step up in type size without layout breakage.*
