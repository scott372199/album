## 1. 目标

在 v1 已上线的静态相册基础上做第二版迭代，解决两件事：

1. **观感**：v1 的浅色杂志风「太素」，重构为 Apple 官网式的科技感与高级感——强排版层级、明暗章节交替、精致动效、沉浸式浏览。
2. **访问**：v1 的 HTTP S3 网站端点有「不安全」提示、URL 长且不便分享，恢复 **HTTPS + 好记的自定义域名**，并把公开桶收敛为私有源。

**成功标准**

- 正式访问地址形如 `https://photos.chenyouyi.top`，浏览器显示有效的 HTTPS 证书，无「不安全」提示、无混合内容。
- 访客能明显感知与 v1 不同的视觉层级与浏览质感；照片仍是主角，且不被裁切、不被滤镜改变。
- 保持 v1 的全部核心能力：时间轴 / 相册 / 搜索筛选 / 灯箱幻灯片 / 增量发布 / 一条本地命令。
- **隐私脱敏这条硬要求不降级**：线上产物仍不含拍摄位置、设备标识、原始文件名。
- 仍是纯静态、无服务器、无数据库、无登录、无运行时依赖；月度成本控制在 ≤ ¥15。

## 4. 功能需求

### FR-01 输入与格式 【沿用 v1】

- 源目录 `photos/`；JPEG / PNG / HEIC / WebP，HEIC 自动转换；一级子目录 = 相册；根目录照片归「未分类」。
- 无 EXIF 拍摄时间用文件修改时间兜底并写入构建报告；内容哈希去重；`photos/.albumignore` 排除规则继续有效。

### FR-02 隐私与脱敏 【硬性要求，不可协商；沿用 + 加固】

- 产物中**不上传原始文件**，只上传重新编码后的展示图与缩略图；重编码即剥离 EXIF，从源头杜绝泄露。
- 移除：GPS 坐标、机身 / 镜头序列号、软件信息、原始文件名、本地绝对路径。
- 保留用于功能的：拍摄时间（仅年月）、宽高比、相册、标签、可选标题 / 说明。
- manifest 字段白名单之外一律不写入；界面不展示 EXIF 参数面板；访客不可下载原图。
- **v2 加固**：S3 桶改为私有，公众无法直接访问桶或列举对象，只能经 CloudFront 读取已发布的静态产物。
- **重要认知**：OAC 私有桶是基础设施加固，**不等于访问控制**。站点本身仍完全公开、无需登录，因此「构建时脱敏」仍是内容隐私的唯一防线，不可降级或省略校验。

### FR-03 时间轴与相册 【沿用 v1，随 FR-06 换皮】

- 首页默认时间轴，按年 → 月分组，每组显示数量与代表图；相册视图按目录分组并可进入单个相册。
- 网格在图片加载前按宽高比占位，避免布局跳动。

### FR-04 搜索与筛选 【沿用 v1，随 FR-06 换皮】

- 前端本地检索，无需后端；关键词（标题 / 说明 / 标签）+ 标签 + 拍摄年月三类条件可组合、实时出结果。
- 无结果时给出明确空状态与「清除筛选」入口。

### FR-05 灯箱与幻灯片 【沿用 v1，增强见 FR-09】

- 全屏；←/→ 或按钮翻页、空格切换 4 秒自动播放、ESC 退出、移动端滑动；预加载相邻图片；在筛选结果集内翻页。

### FR-06 视觉：Apple 官网式科技感 【重写 v1 FR-06】

v1 的「浅色杂志风 / 暖白底 / 衬线体标题 / 克制的细字重说明」整体废弃，替换为以下调性：

- **整体调性**：浅色为主 + 深色章节交替。以纯白与极浅灰为底，穿插近黑的全宽叙事区块，形成 Apple 产品页式的明暗节奏，而不是通篇一个底色。
- **排版**：系统无衬线字体栈（SF Pro / 苹方优先），弃用衬线标题；超大字号主标题与克制的小字号说明形成强字重 / 字号对比；负字距、宽松行距、精确到级的间距节奏。
- **版面**：全宽 hero 区、分章节叙事、大留白、内容最大宽度约束；深浅区块之间用整块切换而非细分割线堆叠。
- **组件语言**：大圆角容器 / 卡片、克制的半透明毛玻璃 sticky 导航、轻量投影仅用于浮层；交互反馈以位移 / 透明度 / 缩放的平滑过渡为主。
- **动效**：滚动进入视口时的渐显与轻微位移、hero 的层次入场、hover 微交互；**必须遵守 `prefers-reduced-motion`**，关闭动效时内容与功能完全可用。
- **交互色**：以克制的单一强调色承载链接 / 焦点 / 选中态，不做多彩渐变堆砌。
- **照片底线（保留 v1 精神）**：**照片本身不裁切、不加滤镜、不加边框、不改变色彩**；容器可以有圆角，但不得靠裁切画面去适配容器。照片仍是页面的绝对主角。
- **可访问性**：图片 alt 文本、键盘可达、焦点可见、文字对比度达标；深色区块上的文字同样达标。
- **跨设备**：手机 / 平板 / 桌面均保持同样调性，不因窄屏退化成朴素列表；无横向溢出。
- **不做**：用户可手动切换的明暗双主题（深色是设计章节，不是主题开关）；不引入外部 CDN 字体 / JS。

> 具体色板、字号阶梯、断点与动效曲线在 `plan.md` 定稿；本节只锁定调性与不可退让的底线。

### FR-07 访问与部署 【重写 v1 FR-07】

- 正式访问走 **HTTPS**，通过 **CloudFront 全球分发 + 自定义域名**：默认 `https://photos.chenyouyi.top`（见 O-02）。
- 需要 **ACM 公共证书**，签发区域必须是 **`us-east-1`**（CloudFront 硬性要求，与 S3 桶所在区域无关）；证书 SAN 覆盖正式域名。
- 域名 DNS 需两条记录：ACM 证书验证记录、正式域名到 CloudFront 分发域名的 CNAME。DNS 记录由你在注册商处添加（见 §7）。
- S3 桶仍在 `ap-southeast-1`，但**关闭静态网站托管、关闭公开读**，改为普通 REST 源站，通过 **OAC（Origin Access Control）** 只允许该 CloudFront 分发读取。
- 桶策略主体改为 CloudFront 服务主体并用 `AWS:SourceArn` 限定分发，**禁止匿名 `s3:GetObject` 与 `s3:ListBucket`**。
- **不引入** CloudFront Function / Lambda@Edge / WAF / API Gateway / 服务器 / 数据库。
- 一条命令完成：构建 → 上传 → 缓存失效 → 输出正式 HTTPS 地址。
- **v1 的 HTTP S3 网站端点在 v2 上线后失效**（桶不再公开、不再启用 website hosting），需明确作为地址迁移说明告知，不留双地址并行。

### FR-08 更新与缓存 【重写 v1 FR-08】

- 增量友好：新增照片放进目录后重跑同一条命令即可，未变化文件跳过处理与上传。
- 产物文件名带内容哈希：**图片 / JS / CSS / manifest 可长缓存**；`index.html` 每次内容变化后**必须让 CDN 缓存失效**，否则访客会读到引用旧清单的入口页。
- 缓存失效范围应最小化（仅入口页优先），避免全站失效带来的额外回源与成本。
- 构建报告继续输出 新增 / 跳过 / 失败 / 无 EXIF 清单；新增：本次是否执行了缓存失效及其结果。

### FR-09 浏览增强 【新增】

- **不裁切网格**：按每张照片原始宽高比自然排布（等比瀑布 / 变高网格），完整呈现横幅与竖幅，不使用 `object-fit: cover` 裁掉画面；仍需占位避免布局跳动。
- **灯箱增强**：支持放大 / 缩小与复位（按钮 + 滚轮 / 双击 / 捏合）、底部缩略图条可点击跳转、显示「第 N / 共 M 张」；v1 的键盘 / 滑动 / 自动播放 / 相邻预加载全部保留。
- **可分享状态**：单张照片、当前视图（时间轴 / 相册）、当前筛选条件写入 URL（**用 URL 片段 hash 表达，不引入服务端重写或边缘函数**）；直接打开分享链接、刷新、浏览器前进后退都能还原到对应照片与筛选状态。
- **分享链接行为**：链接指向正式 HTTPS 域名，落地即打开对应照片的灯箱；链接无效时优雅回落到列表并提示。
- **滚动叙事**：FR-06 的渐显动效不得影响图片懒加载与筛选结果的即时渲染，也不得让键盘焦点顺序错乱。

### FR-10 站点文案 【新增（最小必要）】

- 站点标题与 hero 副标题可配置，**默认值**沿用「个人相册」且副标题留空时 hero 有克制的兜底排版，不出现空洞或错位。
- 照片级标题 / 说明 / 标签的批量编辑**不在 v2 范围**；v1 已有的可选 `photos/tags.csv` 能力继续可用。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 有 CDN 后首屏目标 < 2s（内地访客受跨境链路影响，见 §11.3）；列表只加载缩略图、大图按需加载，清单维持数百 KB 级；上线后记录实测值并与 v1 的 0.18s 做对照 |

| 安全传输 | 全站 HTTPS，HTTP 请求重定向到 HTTPS；页面内无 `http://` 资源引用，无混合内容；证书有效且覆盖正式域名 |
| 成本 | 目标 ≤ ¥15/月：S3 存储 + CloudFront 请求 / 出站 + 证书（ACM 公共证书免费）+ 可选 Route 53 托管区；CloudFront 有长期免费额度，访问量很小时预计仍远低于上限；**实际单价以 AWS 定价页与账单为准** |
| 可维护性 | 无运行时依赖；构建脚本可重复执行、结果可预期；新增照片不需要改代码；配置集中在单一配置文件（桶名 / 区域 / 域名 / 分发 ID） |
| 兼容性 | 最近两个大版本的 Chrome / Safari / Firefox / Edge；iOS Safari / Android Chrome；`backdrop-filter` 等特性需有可接受降级 |
| 可访问性 | 见 FR-06；动效遵循 `prefers-reduced-motion`；深色区块文字对比度达标 |
| 可移植性 | 产物仍是标准静态文件，不绑定特定前端框架；域名与 CDN 配置集中在部署层，便于日后迁移 |

## 6. 明确不做（Out of Scope）

- 登录、账号、权限、私密相册、分享口令、访问控制（**注意：OAC 不是访问控制**）
- 网页端上传 / 删除 / 编辑照片；评论、点赞、社交互动、多用户协作
- 照片级标题 / 说明 / 标签的批量编辑界面；EXIF 参数面板；原图下载
- 地图视图、人脸识别、AI 自动打标；服务端 API、数据库、Serverless 函数
- 用户可切换的明暗双主题；外部 CDN 字体 / JS / 分析脚本
- 几百张规模下的虚拟列表 / 分批渲染、响应式多档图片（如后续出现性能问题，另开 v3）
- CloudFront 中国区分发、WAF、Lambda@Edge、Anycast 静态 IP、Route 53 托管区迁移（除非 O-02 选择根域且 DNS 迁到 Route 53）
- 移动端原生 App

## 7. 部署前置条件与用户侧操作

**已具备（v1 实测 / 用户确认）**

- AWS 账号 `156487532333`，AWS CLI 2.39.6，本地凭证有效；S3 桶 `chenyouyi` 位于 `ap-southeast-1`，已有 44 个线上对象。
- 域名 `chenyouyi.top` 仍持有，**用户能修改其 DNS 记录**。
- Node.js v22.22.2、npm 10.9.7、`/usr/bin/sips` 可用；`sharp` / `exifr` 已安装。

**v2 新增的用户侧操作（不接触密钥，密钥仍只在本地 `aws configure`）**

1. 在 ACM（`us-east-1`）申请证书后，按提示在域名 DNS 添加 **证书验证 CNAME 记录**。
2. 在域名 DNS 添加 **正式域名 → CloudFront 分发域名** 的 CNAME 记录。
3. 等待证书签发（DNS 验证）与 DNS 生效后再执行首次 v2 部署。

> 我会输出精确的待添加记录清单（名称 / 类型 / 值），你在注册商处添加；**不代你登录注册商、不写入任何密钥到项目文件**。

**其他前置条件**

- CloudFront 是全球服务；ACM 证书必须在 `us-east-1`；S3 桶留在 `ap-southeast-1` —— 因此部署脚本需使用**两个区域参数**（v1 v0.2 曾评估过双区域，v2 真正落地）。
- 分发创建后会得到 `*.cloudfront.net` 默认域名，可用于在 DNS 生效前先验证 HTTPS 链路。
- 需确认部署凭证具备 CloudFront 与 ACM 的最小权限（具体策略在 `plan.md` 定稿）。

## 11. 架构核查与已知限制

### 11.1 官方核查结论（2026-11-09 复核）

| 事项 | 结论 | 官方依据 |
| --- | --- | --- |
| S3 网站端点能否提供 HTTPS | **不能**。文档明确「Amazon S3 website endpoints do not support HTTPS」 | [S3 Website endpoints](https://docs.aws.amazon.com/AmazonS3/latest/userguide/WebsiteEndpoints.html) |
| CloudFront 用的 ACM 证书区域 | **必须 `us-east-1`**，与 S3 桶区域无关 | [CloudFront SSL/TLS 要求](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cnames-and-https-requirements.html) |
| 自定义域名要求 | 证书 SAN 必须覆盖该域名；必须有该域名的 **DNS 修改权限** 并添加 CNAME 指向分发 | [CloudFront CNAMEs](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html) |
| 根域（zone apex） | DNS 协议不允许给根域加 CNAME；需 Route 53 Alias 或申请 Anycast 静态 IP —— 故 O-01 默认用子域 | 同上 |
| OAC 与 S3 网站端点 | **不能共用**：OAC 要求普通 S3 REST 源站，桶配置成 website endpoint 时无法使用 OAC | [Restricting access to S3 origin](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html) |
| OAC 下的桶权限 | 桶可保持私有；桶策略授权 `cloudfront.amazonaws.com` 并用 `AWS:SourceArn` 限定分发 | 同上 |
| CloudFront 默认域名 | 创建分发即提供 `d111111abcdef8.cloudfront.net` 并支持 HTTPS，可用于 DNS 生效前验证 | 同上 CNAMEs 文档 |

### 11.2 v2 架构的硬性约束

- **三处区域 / 作用域**：S3 `ap-southeast-1`、ACM `us-east-1`、CloudFront 全球服务；部署脚本不能只带一个 `--region`。
- **桶不再是网站**：关闭静态网站托管后，v1 依赖的「IndexDocument / ErrorDocument = index.html」行为消失。v2 用 URL hash 表达状态（O-07），不依赖服务端重写；同时需保证直接访问分享链接 / 刷新不暴露 S3 错误页（具体配置在 `plan.md`）。
- **缓存**：有 CDN 后「新增照片即时可见」不再天然成立，必须执行入口页缓存失效（FR-08）。
- **证书与 DNS 是外部依赖**：证书 DNS 验证与 CNAME 生效需要等待，首次部署不是纯脚本一步完成；用户侧操作见 §7。

### 11.3 备案与跨境访问的如实说明

- ICP 备案约束的是**中国境内节点 / 服务器**提供的互联网信息服务；**CloudFront 全球区没有中国内地边缘节点**，为自定义域名绑定全球区分发在技术上不需要 ICP 备案。v1 因「备案未获批」而放弃域名的前提，在 CloudFront 方案下不再成立。
- 代价：中国内地访客由境外边缘节点服务，**速度与可用性取决于跨境链路**，不保证优于 v1 直连新加坡 S3；本方案不使用 CloudFront 中国区。
- 另外，AWS 已公告 **CloudFront 中国区（宁夏）将于 2027-05-31 停止支持**，本方案不依赖该服务，不受影响。
- 面向中国内地提供服务的**合规性判断由你自行负责**；本文只陈述技术事实与已知风险，不构成合规结论。若日后需要境内节点与 ICP 备案路径，须重开 spec。

### 11.4 其他已知限制（接受）

- 证书与 DNS 由外部注册商托管，后续证书续期由 ACM 自动管理，但 **DNS 验证记录需保持有效**。
- CloudFront 分发创建 / 更新有传播延迟，部署不像 v1 那样「上传完立刻全量可见」。
- 站点仍完全公开：知道域名即可访问全部照片，**隐私完全依赖构建时脱敏**。
- 滚动渐显与大量 DOM 在几百张规模下可能带来卡顿；v2 不做虚拟列表，作为已知限制跟踪。
- `backdrop-filter` 等新特性在旧浏览器上需有可接受降级。

### 11.5 临时预览期上线节奏（实施补充，2026-11-09；不改动以上需求）

- **触发原因**：CloudFront `CreateDistribution` 被 AWS 账号级验证拦截（需用户提 Support case），HTTPS 与自定义域名无法按期开通。
- **用户决策**：先把 v2 前端发到现有 S3 website endpoint 在线验证效果，**账号验证成功后再绑定 HTTPS 与自定义域名**。
- **性质：上线节奏调整，不是需求变更**。FR-01 ~ FR-10、§7 用户侧操作、§9 上线验收清单全部不变，正式交付地址仍为 `https://photos.chenyouyi.top`；按「变更控制」不触发 spec 重新确认。
- 临时地址 `http://chenyouyi.s3-website-ap-southeast-1.amazonaws.com` **仅用于过渡期人工查看效果，不是交付地址**：它是 HTTP、无 CDN、无缓存失效、桶仍公开、website hosting 仍启用，且沿用 v1 的 `ErrorDocument: index.html`（缺失资源返回首页 HTML 而非 404），行为与正式站点不同，**不得据此判定 §9 验收通过**。
- 过渡期约束：不改桶策略 / 不启用 OAC 私有化 / 不关闭 website hosting / 不做 CloudFront 缓存失效 / 不绑定域名；保留 v1 入口页备份与一键回滚。正式上线时由 `npm run deploy` 的 `--delete` 清理 v1 遗留对象。
