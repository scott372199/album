## 1. 目标

v2 已经把「Apple 官网式的浅色 + 深色章节、超大标题、毛玻璃导航」搭起来了，但仍然被评价为「太素」。**诊断**：问题不在配色，而在三件事——

1. **照片没有被放到足够大的位置**。v2 的照片全部躺在等高行里，尺寸被版式压平；没有一个满屏的、会呼吸的主视觉。
2. **页面缺少节奏与动势**。滚动只有淡入，没有尺度变化、视差、章节切换的仪式感，页面像一张静态清单。
3. **只有静图**。没有视频、没有动图，也就没有「活」的感觉——而手机相册最打动人的恰恰是 Live Photo / 短视频那一下。

同时缺两件工程与场景上的事：**代码没有版本管理**，以及**它还不能当一面真正的照片墙**（平板一直开着）。

**v3 四件事**

1. **可维护**：纳入 Git 仓库、推送 GitHub、`.gitignore` 严谨到「不可能误传照片与密钥」。
2. **眼前一亮**：照片主导的全宽编排，大图 + 小图 + 视频/动图混排，滚动叙事与转场动效。
3. **讲故事**：类似 iPhone「回忆」/ Samsung 相册的故事模式——带章节、标题卡、Ken Burns、节奏可调的全屏放映。
4. **常驻**：一块平板长期开着的照片墙模式——自动轮播、屏幕常亮、夜间调光、新照片自动上线不被旧页面卡住。

**成功标准**

- 访客打开首页 3 秒内能明确感知「这是一页照片，不是一份列表」：首屏被一张照片占满，标题压在照片上；向下滚动有明确的章节节奏。
- 网格里同时存在大图（视觉锚点）、小图（密度）与视频/动图（动势），三者按内容自然混排，不做等大方阵。
- 至少一条视频可在网格内静音预览、点击后有声播放；进度、暂停、静音可控。
- 故事模式能一键播放一段 1~3 分钟的「今年/某相册」放映，有章节标题、转场与结束卡，全程无需操作。
- 平板打开照片墙模式后可无人值守连续运行 8 小时以上：屏幕不自动熄灭（在浏览器允许的范围内）、自动换图、新发布照片在 30 分钟内自动出现、夜间自动变暗。
- 代码在 GitHub 上可追溯：每次迭代一个里程碑提交；仓库内 **0 张照片、0 个密钥、0 个构建产物**。
- 保持 v2 全部硬约束：纯静态、无服务器、无登录；照片不裁切、不滤镜；产物不含 GPS / 序列号 / 原始文件名；成本仍 ≤ ¥15/月。

## 3. 角色与场景

**主人（发布者）**

- US-15：照片放进目录、一条命令构建上传；代码改动先提交再推 GitHub，随时能回到任一版本。
- US-16：想换首屏主图 / 挑几张做精选，改一个配置文件即可，不必动代码。

**访客（远程浏览）**

- US-17：打开即被一张满屏照片迎接；滚动时照片与文字按章节推进，不觉得在「翻列表」。
- US-18：看到视频缩略图能先静音预览几秒，想看完整就点开，有声音、能暂停。
- US-19：点「故事」看一段自动放映，像手机相册的「回忆」。

**家庭观众（客厅/书房平板，常驻）** ← v3 新增核心场景

- US-20：平板插着电放在桌上，打开某个地址就进入照片墙；一整天自己换图，不用碰它。
- US-21：晚上不会刺眼；白天不会因为自动锁屏黑掉。
- US-22：我在电脑上发布新照片，半小时内平板上自己出现，不需要去手动刷新。

**放映者（临时场景）**

- US-23：朋友来家里，点一下开始故事模式，全屏放一段，中途可暂停、可跳过章节。

## 4. 功能需求

### FR-11 Git 与仓库治理 【新增】

- 初始化 **Git 仓库**（默认分支 `main`），把 v1 → v2 → v3 的关键节点整理成**里程碑提交历史**；提交信息采用 `type(scope): 摘要` 形式（如 `feat(web): 全宽 hero 与视频块`）。
- 推送到 **GitHub 公开仓库**（O-01，用户已定），remote 名 `origin`；推送前必须先在本地确认「无隐私文件、无密钥、无大文件」。公开仓库的 README 需明确说明「本站照片不随代码发布，代码中不含任何个人影像」。
- **`.gitignore` 必须覆盖且经实测验证**：
  - 依赖与产物：`node_modules/`、`dist/`、`.build-cache.json`、`.build-report.json`
  - 运行时状态与密钥：`.deploy-state.json`、`src/deploy/distribution-config.json`、`src/deploy/iam-policy.json`、`.env*`、`*.pem`、`*.key`、`.rollback-*/`
  - 源素材（含新增视频）：`photos/**`（仅保留 `.gitkeep` / `tags.csv` / `.albumignore`）
  - 系统与编辑器：`.DS_Store`、`*.log`、`.idea/`、`.vscode/`
- **仓库安检脚本**（新增 `npm run check:repo`）：扫描暂存区与工作树，命中以下任一即失败并给出文件路径——图片/视频扩展名、> 5MB 的文件、疑似密钥（`AKIA`、`BEGIN PRIVATE KEY`、`aws_secret_access_key`、`ghp_`）、绝对路径 `/Users/<name>/`。
- 提供**最小 README**：项目是什么、目录结构、三条命令（build / deploy / check:repo）、隐私声明、为什么不入库照片。
- **边界**：不引入 Git LFS、不做 CI 自动部署、不用 GitHub Pages 托管站点（站点仍在 S3/CloudFront）。

### FR-12 短视频与动图 【新增】

- **输入**：`photos/` 内支持 `.mp4` / `.mov` / `.m4v`；与照片同一套扫描、相册归属、去重规则（内容哈希）。
- **转码**：统一转成浏览器兼容的 H.264/AAC MP4（`faststart`），默认最长边 1080p、时长 ≤ 30s、单条 ≤ 20MB。超出 30s 则截取前 30s 并重新压缩；压缩后仍超 20MB 则只保留封面、按静态图处理，并在构建报告中标记。
- **元数据剥离（硬要求）**：转码必须清除容器与流上的全部元数据——GPS、设备型号、镜头、软件、自定义/厂商标签、原始文件名；同时不得在产物文件名或目录中体现原文件名。
  - **但排序需要时间**：转码**前**先读取视频的拍摄时间（容器 `creation_time`，缺失则用文件修改时间），只取**年 / 月**写入 manifest，与照片规则完全一致；转码后再断言产物无元数据。视频与照片同级对待，不得出现「照片脱敏了、视频漏了」。
- **封面**：自动生成 `poster.webp`（取首帧或 1s 处），供网格与视频未播放时显示，避免白块。
- **网格内预览**：视频块封面带播放标识；桌面端指针悬停、移动端与照片墙进入视口时**静音、行内、循环**播放；离开视口或指针移出立即暂停并回到封面。移动端不得自动播带声音的媒体。
- **灯箱内播放**：点击进入后有声播放（受浏览器自动播放策略约束，用户点击即已获得授权），提供播放/暂停、进度、静音切换、全屏；键盘空格改为播放/暂停（与图片翻页冲突见 O-09）。
- **动图**：`.gif` / 动画 WebP 默认转成 MP4 循环（体积可降一个数量级），仍按视频对待；不支持动的格式按静图处理。
- **Live Photo**：同名的 `HEIC + MOV` 视为一条内容、MOV 作为动效来源，默认**开启自动配对**（O-10）；不配对时各自独立成条。
- **排序与筛选**：视频参与时间轴、相册、标签、年月筛选，与照片无差别；可单独筛「仅视频」。
- **成本控制**：视频是唯一可能显著抬高流量的内容类型，默认限制单条时长与体积，并在构建报告汇总「视频总时长 / 总体积」。

### FR-13 故事模式 【新增】

调用 iPhone「回忆」的核心体验，**不追求自动剪辑成片，而是浏览器内的实时放映**。

- **入口**：导航「故事」按钮 / `#story` / 相册与年份章节上的「播放这个故事」。
- **故事范围**：由当前上下文决定——全部照片、某个相册、某个年份、某个筛选结果、精选集。
- **结构**：自动分章（按年 → 月，或按相册），每章开头一张**标题卡**（如「2026 · 五月」+ 该章张数），章内逐张推进。
- **转场**：Ken Burns（缓慢推拉/平移，方向随图片横竖变化）+ 交叉淡入；竖图与横图用不同的构图位移，避免「同一套动效套所有图」。
- **节奏**：每张默认 4.5~5.5 秒（按图片横竖与是否有文字微调）；提供「慢 / 标准 / 快」三档，切换后立即生效；视频按自身时长播放（超长则截前 30s 并淡出）。
- **控制**：点击/空格暂停与继续；←/→ 上一张/下一张；↑/↓ 或按钮切换章节；ESC 退出；移动端左右滑动切章、单击暂停。控制条 3 秒无操作自动隐藏。
- **进度**：底部细进度条（当前张 + 总进度）+ 章节名；「第 N / 共 M 张」不强制显示。
- **结束卡**：显示本次故事覆盖的年份跨度、张数、相册数，提供「再看一次 / 回到照片」。
- **可退出可回溯**：任意时刻退出，回到进入前的滚动位置与筛选状态；当前张可一键在灯箱中打开。
- **音乐**：默认**不做**（版权与素材成本），详见 O-06；若后续提供本地音频文件，作为可选背景音，且必须可一键静音、默认静音。
- **性能**：预加载下 2 张、预解码；不一次性把全部大图塞进内存；长时间放映不得持续增长内存（回收已过图片）。
- **无障碍**：`prefers-reduced-motion` 时取消 Ken Burns 与视差，改为硬切 + 淡入；提供暂停。
- **不做**：不做视频导出成片、不做人脸/场景识别自动选题、不做 AI 配乐。

### FR-14 照片墙模式（常驻平板）【新增】

面向「一块平板长期开着当照片墙」的场景，v3 的**核心新能力**。

- **入口**：导航「照片墙」按钮 / `#wall`；进入即全屏、隐藏所有 UI（3 秒后控制条淡出，轻触任意位置唤出）。
- **播放**：全屏满幅显示（不裁切，留黑或深色底），自动轮播，默认 10 秒/张，提供 5 / 10 / 20 / 30 秒与「仅视频」等选项；Ken Burns 缓慢推拉；交叉淡入切换；视频自动静音播放，播完再切（不打断）。
- **屏幕常亮**：使用 Screen Wake Lock 保持屏幕不熄灭；**必须由用户手势触发**（进入按钮即手势），页面重新可见时自动重新申请。该 API 只在**安全上下文**（HTTPS 或 localhost）可用——这意味着临时 HTTP 预览地址上常亮不会生效，必须在本地 `localhost` 或正式 HTTPS 域名上验收。
  - **已知限制（必须如实告知）**：iPadOS/iOS 16.4+ 的 Safari 标签页支持，但 **「添加到主屏幕」的独立模式下不生效**（WebKit bug 254545）。因此照片墙推荐**用 Safari 标签页打开**，不要用 PWA 独立窗口；低电量模式下系统可能强制释放，需提示。
  - 提供「若屏幕仍会熄灭」的兜底指引：iPad 设置 → 显示与亮度 → 自动锁定 → 永不（并提示耗电与烧屏风险）。
- **夜间调光**：默认 22:00–07:00 叠加暗色遮罩并降低动效速度（不改变照片本身色彩）；可关闭。
- **防烧屏**：静态元素（时间/日期）位置做极缓慢的像素级位移；夜间降低亮度；长时间停留同一画面的场景给出提示。
- **信息叠加（StandBy 式）**：默认显示时间（大字号）+ 日期 + 简短星期，极简排版、低对比不抢画面；仅显示时间时按分钟刷新，不每秒重绘。可关。
- **内容策略**：默认「**On This Month 优先** → 新照片 → 全部随机洗牌」：每天开场先放几张与今天同月的往年照片（标注「2024 年 5 月」这类文案），没有则跳过。可选「仅精选」「某个相册」「纯随机」。
  - **隐私约束（重要）**：v2 起 manifest 的拍摄时间只保留**年月**，不含「日」。真正的「同一天」需要新增 `dayOfMonth` 字段，属于隐私粒度的**放宽**，因此默认**不做**；是否开启见 §8 O-15。若你选择开启，文案才可写成「三年前的今天」，否则一律用「往年的这个月」。
- **自动更新**：常驻页面每 10 分钟探测一次内容版本；有新照片时**不刷新页面**，在当前播放间隙把新内容并入队列；探测失败静默重试（指数退避），不弹错误。
- **健壮性**：断网时继续播已缓存内容并显示极轻提示；连续运行 8 小时不得出现内存暴涨或卡死；系统挂起后回到前台自动恢复播放与常亮。
- **退出**：ESC / 双击退出到普通浏览。
- **不做**：不做真正的设备锁定（kiosk）——那属于 iPad「引导式访问」，由用户在系统侧开启（见 §7）。

### FR-15 视觉 v3：照片主导的编排 【重写 v2 FR-06 / FR-09 的版面部分】

v2 的调性（浅色为主 + 深色章节、系统无衬线、超大标题、毛玻璃导航、克制的单一强调色）**保留**；v3 在此基础上把「照片」推到绝对主角，并建立清晰的**视觉节奏**。

- **首屏（Hero）**：一张照片满幅铺满首屏（不裁切构图的前提下取最合适的出血方式），站名与一句话压在照片上，字色随照片明暗自适应；照片有极缓慢的推拉（可关）。**这是 v3 与 v2 最大的观感差别。**
- **章节节奏**：整页由若干「章节」组成——开场（hero）→ 精选（编辑式大图）→ 年份/时间线 → 相册 → 故事入口 → 照片墙入口 → 深色收尾。章节之间用整块明暗切换、大留白与全宽图断开，不做细线堆叠。
- **编辑式混排（大图 + 小图）**：网格不再是均质等高行。每个年份/相册开头有 1~2 张**大图（跨 2 栏 / 近全宽）**作为锚点，其余为小图；大图由「精选」或首张决定。**任何尺寸下都不裁切画面**，靠容器与留白适配，必要时允许竖图与横图不同列宽。
- **视频块**：视频在网格中占 1 或 2 栏，封面即内容，带极简播放标识；与照片混排形成「静 → 动 → 静」的呼吸。
- **动势**：滚动驱动的渐显/位移/视差（照片轻微反向位移）、章节标题的字重与位移、网格项错峰入场；**只用 transform / opacity**，不触发重排。
- **转场**：从网格点开照片时，图片从原位置连续放大到灯箱（共享元素过渡），关闭时回落；不支持该能力的浏览器退化为淡入，不得报错或白屏。
- **文字层**：超大标题 + 极克制说明的强对比继续保留；新增「章节序号 / 年份」这类编辑式小字，强化刊物感而非装饰感。
- **照片底线（不可退让）**：照片不裁切、不加滤镜、不加边框、不改变色彩、不加水印；容器可有圆角与留白；视频同理不得加滤镜。
- **跨设备**：手机单列也要有大图—小图的层次（不能退化为等比列表）；平板是重点适配对象（768~1366 宽度区间要好看，这是照片墙的载体）。
- **可访问性**：所有动效遵循 `prefers-reduced-motion`；键盘可达、焦点可见；深色区块文字对比度达标；视频有字幕位（不强制）与静音默认。

### FR-16 加载与性能 【重写 v2 FR-09 的性能部分】

- **三档图**：`thumb`（约 320w，网格小图）/ `grid`（约 768w，网格大图与平板）/ `view`（长边 2048，灯箱与照片墙）。用 `srcset` + `sizes` 按视口与 DPR 选择，避免在 iPad 上把 2048 图当小图拉。
- **占位**：每张图生成极小的模糊占位（内联 data URI），先糊后清，**不允许出现白块或布局跳动**；宽高比在 HTML 里写死。
- **首屏**：hero 图 `fetchpriority=high` 且不懒加载；其余一律懒加载；关键样式随入口页一同到达，不得出现样式闪白（FOUC）。
- **大列表**：分批渲染（默认每批 60 张，滚动到底加载下一批），保证几百张时首屏仍然快；筛选切换不得整页重建导致跳回顶部（除主动改变视图）。
- **预算**：首页 JS ≤ 60KB（gzip 前）、CSS ≤ 30KB；无第三方运行时；首屏可交互 < 2s（本地 CDN 命中）；照片墙模式单次切换不得造成明显掉帧（目标 60fps，最差 30fps）。
- **缓存**：沿用内容哈希长缓存 + 入口页失效。
- **弱网**：视频 `preload="none"`，封面先出；加载失败显示可重试的占位，不静默留白。

### FR-17 站点配置扩展 【扩展 v2 FR-10】

- `site.json` 支持：标题、副标题、**hero 指定**（某张照片 id / 「最新」/「随机固定」）、**精选集**（照片或相册 id 列表，决定大图锚点与故事默认范围）、照片墙默认参数（间隔、是否显示时间、夜间时段）。
- 全部为**可选**，缺省时有合理兜底（无精选时按「每年最新一张」自动生成），不配置也能正常上线。
- 配置改动只影响构建产物，不引入后台。

### FR-18 隐私与脱敏（v3 增量）【硬性要求】

- 沿用 v2 全部约定（不上传原文件、重编码剥离 EXIF、manifest 字段白名单、界面无 EXIF 面板、不可下载原图）。
- **新增**：视频转码后必须验证不含元数据（GPS / 设备 / 拍摄时间 / 原始文件名）；封面图不得残留元数据。
- **新增**：`manifest` 只增加功能必需字段（媒体类型、时长、封面路径、宽高比），**不写原始文件名与路径**。
- **新增**：`.gitignore` + 仓库安检脚本构成第二道防线（照片与密钥不入库）。
- **重要认知**：**公开** GitHub 仓库与私有 S3 桶都**不是访问控制**，站点本身仍然公开；构建时脱敏仍是唯一内容防线。

## 10. 决策记录

| 轮次 | 决策项 | 结论 |
| --- | --- | --- |
| 1 | v3 方向 | 用户提出五项：①git + GitHub + gitignore ②视觉再升级（参考 apple.com，大图/小图/动图、短视频预览）③故事/幻灯片模式（参考 iPhone/Samsung 相册）④平板长期常驻当照片墙 ⑤征求其他点子与新技术 |
| 1 | 推进方式 | 沿用 **逐阶段确认**：spec → plan → tasks，每份写完停下 |
| 1 | 部署 | v3 **不改部署架构**，仍走现有 S3 预览，CloudFront 账号验证通过后切正式域名 |
| 2 | GitHub 仓库可见性 | **公开**（代码不含照片与任何凭证；桶名/域名可见可接受） |
| 2 | 额外提案取舍 | 仅纳入 **A-1 / A-3 / B-1 / B-2**；A-4 / A-5 / A-6 / A-7 / A-8 / B-3 / B-4 留 v4；C 类不做 |
| 2 | 视频素材 | 用户会自行把真实视频放入 `photos/`，实现阶段等素材到位再验收 |

**v2 → v3 的关键前提变化**

- v2 未纳入版本管理，v3 补上（且「不入库照片」让公开/私有仓库的风险都可控）。
- v2 的性能前提是「纯静图、几百张」；v3 引入视频后，**流量与解码成本成为新的约束**，因此有明确的时长/体积上限与 `preload="none"`。
- v2 只考虑「访客打开一次」；v3 引入「页面开着几十天」的常驻场景，**页面生命周期、常亮、热更新、内存**都成为一级需求。

## 11. 技术核查与已知限制

### 11.1 已核查事项（2026-11-09）

| 事项 | 结论 | 依据 |
| --- | --- | --- |
| Screen Wake Lock 在 iPad 可用性 | Safari/iPadOS **16.4+ 支持**（需 HTTPS 或 localhost、需用户手势、页面可见） | WebKit 16.4 实现；MDN/caniuse |
| PWA 独立窗口的 Wake Lock | **不生效**（WebKit bug 254545，「添加到主屏幕」的独立 web app 内失效） | 浏览器兼容数据脚注 |
| 低电量模式 | 系统可能强制释放常亮锁 | 同上，需在指引中提示 |
| CSS 滚动驱动动效（`animation-timeline: view()`） | **Safari 26+**，2026-10 Baseline 新可用；旧版本忽略该属性 | caniuse / web-features |
| 结论 | 动效必须**渐进增强**：默认内容可见，`@supports` 命中才加动效，JS 兜底（IntersectionObserver） | — |
| 视频自动播放 | Safari 要求 `muted` + `playsinline` 才允许无声自动播放；有声播放需用户手势 | Safari 媒体策略 |
| iPhone 视频元数据 | ffmpeg 转码加 `-map_metadata -1` 可清容器与流元数据；HEVC 需转 H.264 保证跨浏览器 | ffmpeg 文档 |

### 11.2 已知限制（接受）

- 平板长期亮屏有**烧屏与耗电**风险，尤其 OLED；v3 只能做调光与像素位移，不能替代系统层面的省电策略。
- Safari 长时间前台可能被系统回收或被「标签页休眠」影响，热更新探测会失败重试，恢复后自动续上；极端情况下仍需手动刷新。
- 滚动驱动动效在旧 Safari（<26）不可用，观感会有差异（内容不受影响）。
- 视频是本项目唯一的重资产，单条限制 30s / 20MB 是成本与体验的折中。
- **临时 S3 预览是 HTTP**：Screen Wake Lock（常亮）在该地址上不可用，因此照片墙的「常亮」只有在本地 `localhost` 或 CloudFront 正式域名上才能完整验收；其余照片墙行为（轮播、调光、热更新）在 HTTP 下可验证。
- **仓库公开**：桶名 `chenyouyi`、域名 `photos.chenyouyi.top`、部署脚本与 IAM 策略模板对所有人可见。这些**不含凭证、不含照片**；但意味着别人能看出站点架构。日后可改为私有，但**已公开的历史可能已被 fork 或缓存，无法彻底收回**——所以「一开始就别提交敏感内容」是唯一可靠的做法。

### 11.3 成本影响

- 照片墙若 10s 一张、全天运行，单台设备每天约 8000+ 次图片请求；命中浏览器缓存与 CDN 后实际回源有限，但仍会抬高 CloudFront 出站。v3 在构建报告里给出「一次轮播的总字节数」，便于判断是否需要降低档位或延长间隔。
- 视频按 3~8MB/条估算，播放一次的成本是照片的 10 倍以上；因此网格只放静音预览（可设只在悬停时触发）。

## 12. 创意与新技术提案池（A-1 / A-3 / B-1 / B-2 已纳入 v3，其余留 v4）

### A. 建议做（低风险、直接提升「照片墙」长期体验）

| 编号 | 点子 | 价值 | 成本 | 说明 |
| --- | --- | --- | --- | --- |
| A-1 | **On This Day（往年的今天）** | 高 | 低 | 照片墙每天开场先放「三年前的今天」，情感回报最高的一招 |
| A-2 | **精选集人工策展** | 高 | 低 | 你挑 10~20 张做「最佳」，hero 与故事优先用它们；不挑则自动生成 |
| A-3 | **StandBy 式大时钟叠加** | 中高 | 低 | 照片墙左下角大字号时间 + 日期，极简排版，兼具实用与装饰 |
| A-4 | **主色提取做章节底色** | 中高 | 中 | 构建时从照片取主色，做章节背景的极浅染色；**不改照片本身**，但会让页面「有氛围」 |
| A-5 | **照片墙模式轮换** | 中 | 中 | 单张 / 拼贴（2×2）/ 故事片段 三种形态定时轮换，避免长期同一节奏 |
| A-6 | **年度回顾（Annual Recap）** | 中高 | 中 | 每年自动生成一段 60s 故事 + 统计卡，年底看很有仪式感 |
| A-7 | **打印样式（可导出 PDF 相册）** | 中 | 低 | 纯 CSS `@media print`，能把某年/某相册打成册子 |
| A-8 | **OG 分享卡片** | 中 | 低 | 分享链接时显示封面图与标题，不再是一行裸链接 |

### B. 建议做（技术升级，但需要你确认值不值）

| 编号 | 新技术 | 价值 | 风险 | 说明 |
| --- | --- | --- | --- | --- |
| B-1 | **View Transitions（共享元素转场）** | 高 | 低 | 网格→灯箱连续放大，是「高级感」最便宜的来源；不支持则淡入 |
| B-2 | **CSS 滚动驱动动效** | 高 | 低 | 视差与入场不再吃 JS，滚动更顺；Safari 26+ 生效 |
| B-3 | **AVIF 图片格式** | 中高 | 低 | 同画质比 WebP 小 20~30%，直接降流量；Safari 16.4+ 支持，需保留 WebP 兜底 |
| B-4 | **Service Worker 离线缓存** | 中高 | 中 | 断网/弱网也能看，照片墙更稳；但要处理版本更新与缓存膨胀 |
| B-5 | **PWA 安装（全屏无地址栏）** | 中 | 中 | 更像原生相册；但独立窗口 **Wake Lock 失效**，与「常亮」冲突 |
| B-6 | **视频 HLS 自适应码率** | 低 | 高 | 需要切片与多码率，复杂度与收益不成正比，建议不做 |
| B-7 | **WebGL / WebGPU 转场** | 低 | 高 | 视觉上限更高，但性能与兼容性风险大、维护成本高，建议不做 |

### C. 记录但不做（说明理由）

| 编号 | 点子 | 理由 |
| --- | --- | --- |
| C-1 | 人脸聚类 / 人物相册 | 需要本地或服务端模型，隐私与体积都不合适；静态站做不了 |
| C-2 | AI 自动打标 / 自动选题 | 需要模型与算力；构建时调用云 API 会引入密钥与成本 |
| C-3 | 地图足迹 | 与「不保留 GPS」的隐私底线直接冲突 |
| C-4 | 家庭共享上传 | 需要后端、账号与存储权限，属架构变更 |
| C-5 | 原生 App / 桌面端 | 与静态站定位冲突，iPad 用浏览器足够 |
| C-6 | 背景音乐（版权曲库） | 版权与体积成本高；仅接受你提供的本地音频 |

**2026-11-09 用户决定**：**A-1（On This Month）/ A-3（StandBy 式时钟）/ B-1（View Transitions）/ B-2（CSS 滚动驱动动效）纳入 v3 范围**，已分别写入 FR-14 与 FR-15；其余 A / B 项留待 v4，C 类不做。
